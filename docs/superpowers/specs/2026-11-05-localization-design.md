# Localization (Simplified Chinese first) — design

Date: 2026-11-05 · Refs #136

## Intent

A user in China asked for a Chinese version (#136). Another user offered help with more languages. The owner wants Ischys usable in other languages, but this is a hobby project maintained by one person, so two things matter more than coverage:

1. **Nothing offensive, political or embarrassing ships under the owner's name.** That is the one outcome that would make this a failure even if everything technically works. Clumsy-but-harmless wording is acceptable and gets fixed later.
2. **Low maintenance and full owner control.** No translation PRs from strangers. All translations are generated by tooling the owner runs, checked by Claude, and committed by the owner. Native speakers suggest fixes only as comments on the GitHub issue.

## Goals

- The phone app (iOS and Android, one Expo codebase) shows its own text in Simplified Chinese when the phone's language is Chinese.
- Built-in exercise names (736), muscle names (17), muscle groups, category names (7) and equipment values are shown in Chinese.
- The iOS Health permission prompts (`NSHealthShareUsageDescription` / `NSHealthUpdateUsageDescription`) and the matching Android text, if any, are localized through app config.
- Exercise search matches both the Chinese and the English name.
- Adding the next language later is mostly "run the translation script again with a new target".
- Any string without a translation falls back to English, per string, never a crash or a blank.

## Non-goals (v1)

- Watch app (SwiftUI), Wear OS app (Kotlin), widget and Live Activity UI chrome stay English. Notification text stays English.
- How-to steps (the long instruction paragraphs on each exercise) stay English.
- No in-app language picker. The app follows the system language; users can override per app with the OS per-app language setting (iOS Settings › Ischys › Language, Android 13+ app language).
- No other languages in v1. Russian or others come later, only after someone asks for a specific language.
- No store listing translation (App Store / Play text) in v1.
- No right-to-left support.

## Anti-goals

- Shipping any string whose back-translation was flagged as rude, political, slang, or meaning something different from the English.
- Exports, backups, CSV and the database storing translated names. Data stays language-independent: a backup made on a Chinese phone must restore identically on an English one.
- Accepting translation files from contributors.

## Decisions (the owner's)

- **Languages:** Simplified Chinese (zh-Hans / zh-CN) only in v1.
- **Who translates:** DeepSeek generates zh-Hans through its API. For future European languages: Claude or DeepL.
- **Review:** Claude back-translates every generated string to English and flags problems; flagged strings are re-generated or left in English. The owner commits the result.
- **Release:** ship once Claude's checks pass. The native reviewer on #136 (RainRespite) reports fixes in the issue afterwards; fixes go into the next update. No pre-release review round.
- **Scope split:** UI text + exercise / muscle / category names now; how-to steps later.
- **Credit:** helpers are credited in release notes / README, not via commits.

## The translation pipeline

A script in the repo (e.g. `frontend/scripts/translate.mjs`, exact location is the builder's call):

- Reads the English source strings (UI strings + catalog names) and their context notes.
- Sends only strings that are new or whose English changed since the last run (track a hash of the English per key), in batches, to the DeepSeek API.
- Reads the key from the `DEEPSEEK_API_KEY` environment variable. It is in the owner's `~/.zshrc`; a non-interactive shell may need `source ~/.zshrc` first. The key must never be written to the repo, logs or output.
- The prompt includes: the glossary below, a per-string context note (where it appears, e.g. "button label", "exercise name", "settings row subtitle"), placeholder rules, and an instruction to use plain, neutral, standard gym terminology with no idioms, jokes or creative phrasing.
- Writes results into the zh-Hans translation file(s), keeping placeholders (`{count}` etc.) intact. The script validates placeholders match the English and rejects the string otherwise.
- Hand-edited translations (fixes from issue comments) must not be overwritten by a re-run unless the English changed.

**Who runs it:** Claude runs the script (the owner asked for this and set up the key), spends the credit, does the safety check and the layout check, and prepares the commit; the owner reviews the report and merges. This plan includes the real first run, not just the tooling.

**How the safety check runs:** inside the Claude Code session, not via the Anthropic API. There is no `ANTHROPIC_API_KEY` and none is needed. The script writes the new/changed strings (English + zh-Hans + context) to a review file; Claude (split across subagents in batches) back-translates and marks each string `ok` or `flagged` with a reason. The script stores that status per key (alongside the English hash) so later runs neither re-review unchanged strings nor re-generate rejected ones unless asked.

**Safety check (Claude, after each run):** back-translate every new/changed string to English, compare with the source, and produce a short report for the owner: flagged lines (offensive / political / slang / wrong meaning / suspiciously long) and what was done about each. Flagged strings do not ship in Chinese: re-generate, or remove so they fall back to English.

**Budget:** the full first run is expected to cost well under $1 of DeepSeek credit.

## How the app uses translations

- **UI text:** extract the phone app's user-visible strings into keyed English source + zh-Hans file(s). Each key carries a short context note for the translator. Choice of library (e.g. `expo-localization` plus a small i18n library) is the builder's call; keep it light.
- **Language detection:** system locale via the OS; any Chinese Simplified locale (zh-Hans, zh-CN, zh-SG) → zh-Hans; everything else → English. Traditional Chinese (zh-Hant, zh-TW, zh-HK) → English in v1 (it is a different script). Register the supported languages with the OS so the per-app language setting lists Chinese (iOS: `CFBundleLocalizations` via app config; Android: locale config).
- **Catalog names:** built-in exercises, muscles and categories keep their stable IDs and English `name` in the database exactly as today. Translated names are display labels looked up by ID at render time from a bundled table. Nothing in the database, sync, export, import, CSV or backup changes.
- **Custom exercises** (`isCustom = 1`) always show exactly what the user typed.
- **Search:** matches the query against the displayed (Chinese) name and the English name.
- **Sorting:** alphabetical lists sort by displayed name; for Chinese, pinyin-order via `localeCompare` with the zh locale is acceptable.
- **Numbers and dates:** use locale-aware formatting where the app already formats dates; units stay kg/lb.

## Calls made by Claude (owner may override)

- No in-app language picker; OS per-app setting instead.
- If a user has renamed a built-in exercise (its stored name differs from the catalog English), show the user's name, not the translation. This is a heuristic with no schema flag: if some old install holds a catalog name that differs from today's file, that exercise just shows in English, which is a harmless fallback. No schema change.
- The default workout name `'Workout'` stays stored in English; at display time a name exactly equal to the default is shown as 训练. A user who literally typed "Workout" also sees 训练, which is acceptable. Same rule for any other stored default label found during extraction.
- Muscle groups and equipment values are translated the same way as catalog names (display lookup by stored English value/ID; storage unchanged).
- The phone sends the **displayed** (translated) exercise name to the Watch, Wear OS, Live Activity and notification, because those are data, while their own fixed labels stay English. Mixed text on the Watch is accepted for v1.
- Traditional Chinese falls back to English rather than showing Simplified.
- Layout check: Claude runs the zh-Hans build in the iOS simulator and screenshots every screen to catch clipped or overflowing text before release; Android is spot-checked.
