# Localization: Russian (second language) — design

Date: 2026-11-08 · Refs #136

This is an add-on to `2026-11-05-localization-design.md` (the Simplified Chinese design). Everything there applies to Russian unless this document says otherwise. Read that first.

## Intent

khlebobul asked for Russian on #136 (2026-11-08) and will review it after release. The owner's rule from the Chinese work stands: translations are generated by tooling the owner runs, checked by Claude, committed by the owner; native speakers only suggest fixes as issue comments. The top priority is unchanged: **nothing offensive, political or embarrassing ships.** Clumsy-but-harmless wording is acceptable.

Russian carries a political risk Chinese did not: showing Russian to users who did not choose it.

## Goals

- Phones whose language is Russian see the phone app in Russian, with the same coverage as Chinese: all UI text, built-in exercise / muscle / category / group / equipment names, dates, and the iOS Health permission text (plus Android equivalent if any).
- Russian plural forms are correct ("1 подход, 2 подхода, 5 подходов", "21 подход").
- No clipped or overflowing Russian text on any screen.
- The pipeline becomes multi-language: adding a third language later is mostly configuration plus a glossary.

## Non-goals

Same as Chinese: Watch / Wear OS / widgets / Live Activity / notification chrome stay English; how-to steps stay English; no in-app language picker; no store listing translation; no RTL.

## Anti-goals

- **Russian shown to anyone whose phone is not set to Russian.** (Owner's decision.) Ukrainian, Belarusian, Kazakh, Kyrgyz, Uzbek, Georgian, Armenian, Azerbaijani, Moldovan/Romanian and every other language fall back to **English**, never to Russian as a "close" language. Only a first preferred language of `ru` (any region: ru-RU, ru-UA, ru-KZ, ru-BY…) gets Russian.
- Everything in the Chinese anti-goals (flagged strings shipping, translated data in storage/exports/backups, contributor translation files).
- Any Russian string whose back-translation is political, nationalist, slang, crude, or that names countries, flags or regions where the English does not.

## Decisions

### Owner's
- Russian only for phones set to Russian; all other languages get English (above).
- Same process as Chinese: DeepSeek generates; Claude back-translates every string and flags offensive / political / slang / wrong-meaning / suspiciously long lines; flagged lines are re-generated or left English; ship once checks pass; khlebobul reviews afterwards in #136 comments; no translation PRs.
- Release in the next update after it is built.
- **Font:** Space Grotesk (display / title / body) has no Cyrillic. When the app language is Russian, text that uses Space Grotesk uses the platform system font instead (SF Pro on iOS, Roboto on Android), so no line mixes fonts. JetBrains Mono (numbers, mono labels) has Cyrillic and stays. English and Chinese keep Space Grotesk exactly as today. No new font is bundled.

### Claude's calls (owner may override)
- **Release:** next version (4.6) on both iOS and Android. If Android 4.5 has still not been uploaded by then, Android goes straight to 4.6 (it contains everything in 4.5).
- **Plurals:** the translator gains CLDR plural categories per language (`one` / `few` / `many` / `other` for Russian, via `Intl.PluralRules('ru')` or an equivalent pure rule), with English keeping `_one` / `_other` and zh-Hans keeping its single form. The translation script asks DeepSeek for all Russian forms a plural key needs and validates that each form is present and keeps the placeholders. A missing Russian form falls back to English for that string, never a wrong form.
- **Count strings with only one English form** (about 113 strings take a number; only ~27 are `_one`/`_other` pairs, e.g. `home.exerciseCount` "{count} exercises", `history.count`, `{n} REPS LEFT`): Russian gets its own plural forms for these keys without changing their English or Chinese text, keys or review state — Chinese must not need re-review. The translator picks the Russian form from the string's count variable (whatever it is named: `count`, `n`, …), declared per key (e.g. in the key's `en.ts` entry). Where the number is not a count of things, no plural forms. Rephrasing to avoid plurals ("Тренировок: 5") is acceptable where a string is too tight for the full form.
- **Extra safety scan for Russian:** before the back-translation review, the script (or a test) flags any Russian string containing country, nationality, region, flag, political or military words (a deny-list kept beside the glossary) whose English source does not contain the equivalent. Flagged lines are left English unless the review clears them. The back-translation review itself is the same single pass as Chinese.
- **Length:** Russian is typically 20–30% longer than English. The context note tells DeepSeek where space is tight. The script's existing "overlong" check gets a per-language allowance. After the run, Claude checks every screen in the iOS simulator in Russian (Android spot-check, as for Chinese). Where a line clips, ask DeepSeek for a shorter variant (as was done for the Chinese import button) before touching layout; layout changes only where shortening cannot work.
- **Glossary (`glossary.ru.json`), starting set:** set = подход, rep / reps = повторение / повторения (short: повт.), exercise = упражнение, workout = тренировка, routine = программа, warm-up set = разминочный подход, drop set = дроп-сет, failure set = подход до отказа, superset = суперсет, personal record / PR = личный рекорд (abbreviation PR stays Latin), RPE / 1RM stay Latin, kg / lb → кг / фунт only where the app already localizes unit words, otherwise keep as is; Ischys never translated. The builder may extend it; khlebobul may correct it later.
- **Formal vs informal "you":** use neutral impersonal or plural-formal phrasing (вы, lowercase), standard for app UI; no ты.
- **Default stored names:** 'Workout', 'Empty Workout', 'Athlete' are displayed in Russian the same way as in Chinese (`defaultLabels.ts`); stored values unchanged.
- **Sorting and index letters:** alphabetical lists sort with the Russian collator; the exercise library's index letter is the first Cyrillic letter of the displayed name.
- **Dates:** Russian month and weekday names (correct grammatical case in "8 ноября"), either hand-written like the Chinese ones in `format.ts` or via `Intl.DateTimeFormat('ru')` if Hermes on iOS and Android both produce it; builder verifies on both before relying on Intl.
- **Search:** matches Russian and English names, case-insensitive including Cyrillic; treat ё and е as equal.

## What's left to the builder

- How to generalise the zh-only code paths (`locale.ts` `Lang`, `t.ts`, `translate.ts`, `catalogNames.ts`, `labels.ts`, `format.ts`, `translate.mjs` paths and `--lang` check, `app.json` `locales` / `CFBundleLocalizations` / expo-localization `supportedLocales`, the shipped guard) into a per-language setup without changing Chinese or English behaviour.
- File layout for the Russian files (mirroring the zh-Hans ones) and the per-language state file.
- How to switch the font family by language (theme tokens, a font helper, etc.); text measured for the clipping check must use the Russian font setup.
- Tests: locale mapping (ru variants → ru; uk, be, kk, ky, uz, ka, hy, az, ro, and unknowns → en; zh behaviour unchanged), Russian plural selection (0, 1, 2, 4, 5, 11, 12, 14, 21, 22, 25, 101, 111, fractional if counts can be fractional), fallback when a form is missing, placeholder validation per form, Cyrillic search, ё/е, shipped guard for ru.
